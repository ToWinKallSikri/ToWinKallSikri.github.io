Security Operations Centre for SMEs

A resource-conscious home-lab SOC that combines network security tools, virtualisation and custom log decoding.

Overview

Small organisations may not have the budget or staff for a large commercial security operations platform. My thesis explored how an affordable lab could collect, interpret and present security events using a combination of open-source tools and existing hardware.

The system brought together Wazuh, pfSense, Snort, Proxmox and ESXi on an HP ProLiant server. I designed custom decoders for Kea-DHCP4 and the pfSense Captive Portal.

My contribution

  • Designed the network and virtualisation layout for the SOC environment.
  • Integrated Wazuh, pfSense and Snort with Proxmox and VMware ESXi.
  • Wrote custom Wazuh decoders for Kea-DHCP4 and pfSense Captive Portal logs.
  • Validated alert ingestion with a controlled EICAR test and VirusTotal lookup.

How it works

Endpoints and network services produce events. Wazuh collects and processes logs, while custom decoders extract fields from the DHCP and captive portal formats.

Snort and pfSense provide network security components, and the virtualised lab hosts the supporting services. The final topology connects the data sources to the monitoring and dashboard layers.

Key decisions

Reuse available hardware

Choice: Build around an HP ProLiant server and virtualise the lab services.

Why: Reusing hardware kept the project's additional hardware cost to about €150 while allowing multiple components to run in one environment.

Trade-off: A single host concentrates workloads and does not provide the resilience expected in a production SOC.

Decode the logs the tools actually produce

Choice: Add custom decoders for Kea-DHCP4 and the pfSense Captive Portal.

Why: Useful alerts depend on turning source-specific log formats into fields the monitoring platform can interpret.

Trade-off: Custom decoders need maintenance when log formats change and require testing against real event samples.

Use a safe validation artefact

Choice: Use an EICAR test file and VirusTotal as a controlled check of the event pipeline.

Why: This allowed a known test event to exercise ingestion and alert handling without presenting the exercise as a real attack.

Trade-off: The test validates a narrow path through the pipeline, not the SOC's ability to detect every threat.

Results

The thesis delivered a working lab design and demonstrated log ingestion and alert presentation, including a controlled EICAR / VirusTotal validation.

The estimated hardware cost was about €150, based on reuse of the HP ProLiant server.

Limits and next steps

The lab did not include SOAR, and the free VirusTotal API quota constrained repeated lookups. A single physical host also limits availability and scalability.

Next, I would add documented backup and recovery, measure resource use under load, and define a response workflow before extending the environment.
