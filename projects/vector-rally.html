Overview

Vector Rally is a console racing game built around a grid-based movement model. Players choose a direction and speed, and the game checks whether the resulting trajectory stays on the track and avoids collisions.

The project separates the race engine from track parsing, rule enforcement and collision checking so that new track layouts and player types can be added without rewriting the whole game.

My contribution

  • Implemented the Java game structure and Gradle build.
  • Added text-file track parsing so that layouts can be changed without editing the game engine.
  • Built bot racers with randomly assigned speed strategies.
  • Checked movement by splitting trajectories into integer route points and validating track boundaries and collisions.

How it works

The parser turns a text track into the representation used by the game. The race engine advances each racer in turn, while the referee applies the start order and race rules.

Bot racers use assigned speed strategies. Each proposed movement is checked along its route for off-track points and collisions before the turn is accepted.

Key decisions

Separate rules from the race loop

Choice: Keep the referee, collision checker, parser and game engine as distinct parts.

Why: This makes the rules easier to reason about and gives the project a path to additional player types.

Trade-off: The components need clear interfaces so the same rules are applied consistently.

Represent movement as a sequence of points

Choice: Split each move into integer route points before checking it against the track.

Why: Checking intermediate points catches a move that crosses an edge or another car even when its destination appears valid.

Trade-off: This is a discrete game model and does not attempt to simulate continuous vehicle physics.

Load tracks from text files

Choice: Parse configurable track layouts instead of hard-coding one circuit.

Why: It makes it easier to try new routes and separate level design from game logic.

Trade-off: The parser must reject malformed or inconsistent track files cleanly.

Results

The project supports custom tracks and bot-driven races in a console application.

A track concept shows how route ideas informed the design.

Limits and next steps

The game focuses on turn-based route rules rather than vehicle physics, and the bot strategies are intentionally simple.

Next, I would add human player input, more varied bot strategies and automated tests for edge cases in track parsing and collision checking.
