MuniciPath

A municipal information platform that organises local posts and events around map locations, with moderation and contributor roles.

Overview

MuniciPath was designed to make information about Italian municipalities easier to discover. Users browse municipalities and map-based points containing local posts, events and other information.

The project was developed as a group using an iterative process. The report describes shared project outcomes but does not attribute individual features to specific team members, so this page does not claim sole ownership of any component.

My contribution

  • Worked as part of the group that designed and implemented the platform.
  • The shared project scope included a Spring Boot backend, an Angular frontend, REST communication and JWT-based authentication.
  • The group also implemented municipal moderation workflows and Wilson score-based analytics.

How it works

The Angular interface communicates with a Spring Boot backend over REST. JWTs support authentication, with the frontend storing them in cookies as described in the project report.

Municipalities contain map locations and posts. Role permissions govern whether a contribution can be published directly or must first be reviewed; analytics provide municipal views of content performance.

Key decisions

Organise information by place

Choice: Represent municipal content as map locations containing posts, with a special location for municipality-wide information.

Why: The platform's purpose was to help visitors find useful local information in context.

Trade-off: Map-based browsing depends on accurate location data and may not suit every kind of content.

Moderate contributions by role

Choice: Distinguish between tourists, contributors, moderators and municipal curators, with different publishing permissions.

Why: The group wanted public information to remain open to contributions while giving municipal staff a way to review submissions.

Trade-off: Role-based workflows create more states and permissions to test and maintain.

Use Wilson score for ranking

Choice: Use Wilson score analytics for municipal content rather than relying only on raw popularity.

Why: The group wanted the analytics to account for the amount of feedback behind a result.

Trade-off: The score still depends on the quality and volume of user feedback and should be read in context.

Results

The group produced a web application with an interactive map, municipal content, role-based features and the ability to exchange multimedia content between the frontend and backend.

The project report describes four iterations, ending with frontend work, REST integration and testing.

Limits and next steps

The report does not assign individual features to team members. I have therefore described the shared project rather than making an unsupported claim about which parts I personally implemented.

Next, I would add a clear contribution record and test the permission boundaries and token handling as part of a security review.
