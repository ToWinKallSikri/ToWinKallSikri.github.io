Ricostruzione di un file system FAT16

Uno strumento Python per recuperare file da un’immagine FAT16 dopo che una formattazione rapida ha cancellato le voci della directory principale.

Panoramica

Il progetto richiedeva di esaminare un’immagine FAT16 la cui directory principale era stata azzerata da una formattazione rapida. Venute meno le voci di directory, il recupero dipendeva dalla lettura delle strutture del file system e dalla ricostruzione diretta delle catene di cluster.

Ho scritto uno strumento per mappare i cluster e ricostruire i file dall’immagine, confrontando le due copie della FAT e preservando l’immagine come reperto.

Il mio contributo

  • Ho analizzato le strutture FAT16 necessarie a individuare e seguire le catene di cluster dei file.
  • Ho gestito cluster da 2.048 byte e ricostruito i dati a partire dal contenuto grezzo dell’immagine.
  • Ho confrontato FAT1 e FAT2 durante l’analisi delle informazioni di allocazione.
  • Ho verificato l’hash MD5 dell’immagine per controllare che il reperto originale non fosse stato modificato.

Come funziona

Lo strumento legge le strutture del volume, mappa i cluster dei dati con dimensione di 2.048 byte e consulta le voci FAT per seguire le catene dei file.

Le due copie della FAT vengono confrontate. Il contenuto ricostruito viene poi salvato per l’esame, mantenendo l’hash originale dell’immagine come controllo d’integrità.

Decisioni chiave

Lavorare sull’immagine, non sul file system attivo

Scelta: Usare l’immagine disco come fonte dei dati e verificarne l’MD5 prima dell’analisi.

Motivazione: Un’analisi forense richiede un input riproducibile e un controllo che il reperto non sia stato alterato durante la gestione.

Compromesso: Un hash invariato conferma che l’immagine non è cambiata durante l’analisi, ma non dimostra che sia stata acquisita correttamente.

Ricostruire direttamente le catene di cluster

Scelta: Usare le voci di allocazione FAT per ricostruire i file, senza dipendere dalla directory principale cancellata.

Motivazione: Le voci di directory non erano più presenti, mentre le informazioni di allocazione permettevano ancora di seguire i cluster dei dati.

Compromesso: La qualità del recupero dipende dallo stato delle tabelle di allocazione e da quanto la formattazione rapida abbia sovrascritto.

Risultati

La ricostruzione ha recuperato 57 file, 8 directory e 16 sottodirectory.

Tra i file recuperati più rilevanti figurano INVOICE.PDF e TRANSA-1.TXT. I loro contenuti fornivano informazioni coerenti sul wallet usato nell’esercitazione.

Limiti e sviluppi futuri

Una formattazione rapida può lasciare intatte informazioni di allocazione utili, ma il recupero non è garantito se i metadati o i cluster sono stati sovrascritti.

Come passo successivo, aggiungerei un registro più dettagliato delle decisioni prese per ogni catena e segnalerei le incoerenze tra le voci FAT per la revisione manuale.
